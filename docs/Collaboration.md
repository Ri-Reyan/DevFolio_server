৩. GIT WORKFLOW & TEAM COLLABORATION (টিমের কাজ করার নিয়ম)
---

---

ব্রাঞ্চিং আর্কিটেকচার:

- `main` : অফিশিয়াল প্রোডাকশন ব্রাঞ্চ। এখানে সরাসরি কেউ কোড পুশ করবে না।
- `dev` : সেন্ট্রাল ডেভেলপমেন্ট ব্রাঞ্চ। সব ফিচার এখানে এসে ইন্টিগ্রেট হবে।
- `feature/<name>` : কাজের জন্য তৈরি আলাদা সাময়িক ব্রাঞ্চ (যেমন: `feature/navbar-ui`)।

--- [ডেভেলপারদের কাজের ধাপ] ---

ধাপ ১: লোকাল পিসি আপডেট করা
git checkout dev
git pull origin dev
-> কাজ: লোকাল `dev`-এ এসে গিটহাবের লেটেস্ট কোড নিজের পিসিতে নামিয়ে নেয়।

ধাপ ২: নতুন ফিচার ব্রাঞ্চ তৈরি করা
git checkout -b feature/component-name
-> কাজ: `dev` থেকে আলাদা নতুন ফিচার ব্রাঞ্চ বানিয়ে স্বয়ংক্রিয়ভাবে সেখানে চলে যায়।

ধাপ ৩: কোডের অবস্থা পরীক্ষা করা
git status
-> কাজ: কোন কোন ফাইল এডিট বা নতুন তৈরি হয়েছে তা দেখায়।

ধাপ ৪: পরিবর্তনের ফাইলগুলো যুক্ত করা
git add .
-> কাজ: পরিবর্তিত সব ফাইল স্টেজিং এরিয়ায় জমা করে।

ধাপ ৫: স্পষ্ট মেসেজসহ কমিট করা
git commit -m "feat(scope): implement responsive layout"
-> কাজ: মেসেজসহ পরিবর্তনগুলো লোকাল হিস্ট্রিতে সেভ করে।

ধাপ ৬: ব্রাঞ্চটি গিটহাবে পাঠানো
git push -u origin feature/component-name
-> কাজ: আপনার লোকাল ব্রাঞ্চটি গিটহাবে আপলোড করে দেয়।

ধাপ ৭: Pull Request (PR) তৈরি করা

- গিটহাবে গিয়ে "Compare & pull request"-এ ক্লিক করুন।
- Base ব্রাঞ্চ দিন `dev` এবং Compare ব্রাঞ্চ দিন `feature/component-name`।
- কাজের বিবরণ লিখে PR সাবমিট করুন।

--- [টিম লিডারের রিভিউ ও মার্জ করার ধাপ] ---

ধাপ ১: মেম্বারের ব্রাঞ্চ নিজের লোকাল পিসিতে নামিয়ে টেস্ট করা
git fetch origin
git checkout feature/team-member-branch
npm install
npm run dev
-> কাজ: গিটহাবের আপডেট তথ্য টানে, মেম্বারের ব্রাঞ্চে যায়, ডিপেন্ডেন্সি ইন্সটল করে প্রজেক্ট রান করে যাচাই করে।

ধাপ ২: গিটহাবে পিআর অ্যাপ্রুভ ও মার্জ করা

- ব্রাউজারে পিআর চেক করে "Files changed" দেখুন।
- সব ঠিক থাকলে "Merge pull request" -> "Confirm merge" দিন।

ধাপ ৩: নিজের লোকাল `dev` আপডেট করা
git checkout dev
git pull origin dev
-> কাজ: লোকাল `dev`-কে গিটহাবের মার্জ হওয়া লেটেস্ট কোডের সাথে সিংক করে।

ধাপ ৪: প্রজেক্ট রিলিজের সময় `dev` থেকে `main`-এ পাঠানো

- গিটহাবে PR তৈরি করুন: Base: `main` <-- Compare: `dev`।
- মার্জ কনফার্ম করার পর লোকাল মেশিনে চালান:
  git checkout main
  git pull origin main

## ৪. COMMON PROBLEMS & SOLUTIONS (সমস্যা ও কমান্ডসহ সমাধান)

[সমস্যা ১: Merge Conflict (মার্জ কনফ্লিক্ট)]
কারণ: দুইজন ডেভেলপার একই ফাইলের একই লাইনে কোড পরিবর্তন করলে গিট স্বয়ংক্রিয়ভাবে ডিসিশন নিতে পারে না।
সমাধান:
১. ফিচার ব্রাঞ্চে যান এবং dev মার্জ করুন:
git checkout feature/my-feature
git merge dev
২. VS Code-এ ফাইলটি ওপেন করুন। `<<<<<<<`, `=======`, `>>>>>>>` অংশ দেখে প্রয়োজনীয় কোড রেখে বাকি মার্কারগুলো মুছে ফেলুন।
৩. টার্মিনালে সেভ ও পুশ করুন:
git add .
git commit -m "fix(conflict): resolve merge conflict with dev"
git push origin feature/my-feature

[সমস্যা ২: ব্রাঞ্চ সুইচ করতে দিচ্ছে না (Uncommitted changes error)]
কারণ: কাজ অসম্পূর্ণ রেখে বা কমিট না করে অন্য ব্রাঞ্চে যেতে চাইলে গিট কোড হারানোর ভয়ে আটকে দেয়।
সমাধান:
git stash
git checkout dev
git pull origin dev
git checkout feature/my-feature
git stash pop
-> `git stash` বর্তমান কাজ সাময়িকভাবে লুকিয়ে রাখে এবং `git stash pop` তা ফিরিয়ে আনে।

[সমস্যা ৩: ভুল করে `dev` ব্রাঞ্চে কোড লিখে ফেলেছেন (কমিট করার আগে)]
কারণ: কাজ শুরুর আগে ফিচার ব্রাঞ্চ বানাতে ভুলে গেছেন।
সমাধান:
git stash
git checkout -b feature/correct-feature-name
git stash pop
-> কাজগুলো স্ট্যাশে নিয়ে নতুন ফিচার ব্রাঞ্চ বানিয়ে সেখানে আনপ্যাক করে দেয়, ফলে `dev` ক্লিন থাকে।

[সমস্যা ৪: খারাপ কোড ভুলবশত `dev` ব্রাঞ্চে মার্জ হয়ে গেছে (Undo/Revert Bad Merge)]
কারণ: অপরীক্ষিত কোড মার্জ হওয়ায় প্রজেক্ট ভেঙে গেছে।
সমাধান:
১. কমিট হিস্ট্রি থেকে খারাপ মার্জের হ্যাশ আইডি দেখুন:
git log --oneline -n 5
২. সেফলি রিভার্ট করুন:
git revert -m 1 <commit-hash>
git push origin dev
-> হিস্ট্রি নষ্ট না করে খারাপ কোডগুলো বাতিল করে আগের ভালো অবস্থায় ফিরিয়ে আনে।

[সমস্যা ৫: ভুল মেসেজ দিয়ে কমিট করে ফেলেছেন (পুশ করার আগে)]
কারণ: কমিট মেসেজে টাইপো হয়েছে।
সমাধান:
git commit --amend -m "feat(correct-scope): updated commit message"
-> আগের শেষ কমিট মেসেজটিকে নতুন মেসেজ দিয়ে ওভাররাইট করে।

[সমস্যা ৬: .gitignore ফাইল কাজ করছে না (node_modules বা .env গিটহাবে চলে যাচ্ছে)]
কারণ: ফাইলগুলো .gitignore-এ লেখার আগেই একবার গিট ইনডেক্সে বা ট্র্যাকিংয়ে চলে গেছে।
সমাধান:
git rm -r --cached .
git add .
git commit -m "fix(git): clear tracked cache and apply .gitignore"
-> লোকাল ফাইল না মুছে শুধুমাত্র গিটের ট্র্যাকিং ক্যাশ ক্লিয়ার করে নতুন রুল চালু করে।

[সমস্যা ৭: লোকাল ফাইল এলোমেলো হয়ে গেছে, গিটহাবের সাথে হুবহু ১০০% সিংক করতে চান]
সতর্কতা: এতে লোকালের সব আনকমিটেড কাজ ডিলিট হয়ে যাবে।
সমাধান:
git fetch origin
git reset --hard origin/dev
-> লোকাল কোড সম্পূর্ণ মুছে গিটহাবের রিমোট dev ব্রাঞ্চের হুবহু অবস্থায় নিয়ে আসে।

[সমস্যা ৮: Detached HEAD স্টেটে চলে গেছেন]
কারণ: ব্রাঞ্চের বদলে সরাসরি কোনো পুরোনো কমিট আইডিতে চেকআউট করায় এটি ঘটে।
সমাধান:
git checkout dev
-> পুনরায় মেইনস্ট্রিম ব্রাঞ্চে ফিরিয়ে আনে।

## ৫. QUICK GIT COMMAND REFERENCE (চিটশিট)

| কমান্ড                    | কাজ                                              |
| ------------------------- | ------------------------------------------------ |
| git status                | ফাইলের পরিবর্তন ও স্টেজিং স্ট্যাটাস চেক করে      |
| git checkout -b <name>    | নতুন ব্রাঞ্চ তৈরি করে সাথে সাথে সেখানে যায়       |
| git checkout <name>       | বিদ্যমান ব্রাঞ্চে সুইচ করে                       |
| git add .                 | সব ফাইল কমিটের জন্য প্রস্তুত করে                 |
| git commit -m "msg"       | মেসেজসহ স্ন্যাপশট লোকালি সেভ করে                 |
| git push -u origin <name> | লোকাল ব্রাঞ্চ রিমোট গিটহাবে আপলোড করে            |
| git pull origin <name>    | রিমোট থেকে নতুন কোড নামিয়ে লোকাল ফাইলে মার্জ করে |
| git fetch origin          | ফাইল না বদলে রিমোটের ব্রাঞ্চ মেটাডেটা নামিয়ে আনে |
| git stash                 | বর্তমান অসম্পূর্ণ কাজ সাময়িক মেমোরিতে সরিয়ে রাখে |
| git stash pop             | সাময়িক মেমোরি থেকে লুকানো কাজ পুনরায় ফিরিয়ে আনে  |
| git log --oneline         | সংক্ষিপ্ত আকারে কমিট হিস্ট্রি দেখায়              |
| git branch -d <name>      | কাজ শেষ হওয়া লোকাল ব্রাঞ্চ মুছে ফেলে             |
| git reset --hard <target> | সব পরিবর্তন মুছে টার্গেট ব্রাঞ্চে রিসেট করে      |
